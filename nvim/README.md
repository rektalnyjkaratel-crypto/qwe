# Neovim

Минимальный конфиг для Neovim 0.12.5+: Go, Rust, JavaScript/TypeScript,
Svelte/Vite, PHP, Lua и Python.
Рабочий `~/.config/nvim` ссылается на эту папку. Локальная тема `solarized`
использует цвета Solarized Dark из профиля Ubuntu Windows Terminal. Фон и основной
текст совпадают с терминалом, а цвета синтаксиса заданы явно через `termguicolors`.
Дополнительный плагин темы не нужен.

Языковой сервер — отдельная программа, которая даёт подсказки, находит определения
и ошибки в коде. Он запускается только при открытии файла нужного языка.

| Язык | Сервер | Тесты |
| --- | --- | --- |
| Go | gopls | go test |
| Rust | rust-analyzer | cargo test |
| JS/TS, JSX/TSX | typescript-language-server; ESLint при наличии конфига | Vitest, Jest, node:test и другие |
| Svelte/Vite | svelte-language-server; HTML/CSS/JSON/Tailwind/Emmet по файлам | Vitest, Playwright и другие |
| PHP | Intelephense; Psalm в проектах с psalm.xml | PHPUnit или Pest из проекта |
| Lua | lua-language-server | Busted |
| Python | ty | pytest; для проекта с uv.lock — uv run pytest |

## Каждый день

`Пробел` — начало сочетания, клавиши нажимаются последовательно в обычном режиме.
Между клавишами можно делать паузу до 1,5 секунды.

| Клавиши | Действие |
| --- | --- |
| `Пробел ff` | Найти файл в проекте |
| `Пробел e` | Открыть или закрыть explorer справа |
| `Пробел fg` | Найти текст в проекте |
| `Пробел fw` | Найти слово под курсором |
| `Пробел fb` | Открытые файлы |
| `Пробел fs` | Функции и другие символы в файле |
| `s`, текст, подсвеченная буква | Прыгнуть к тексту на экране |
| `[m`, `]m` | Предыдущая/следующая функция или метод |
| `[T`, `]T` | Предыдущий/следующий тип: struct, enum, trait, interface |
| `gd`, `gr`, `gi`, `gy` | Определение, использования, реализация, тип |
| `Ctrl-o`, `Ctrl-i` | Назад и вперёд по переходам |
| `K` | Документация под курсором |
| `Пробел rn`, `Пробел ca`, `Пробел ci`, `Пробел ch` | Переименовать, исправление, imports, включить/выключить inlay hints |
| `Пробел ca` в visual mode | Исправление или LSP-рефакторинг для выделенного кода |
| `Пробел Re`, `RE`, `Rv`, `Ri`, `RI`, `Rs` | Рефакторинг: вынести функцию, вынести в файл, вынести переменную, inline переменной/функции, меню |
| `Пробел cL`, `Пробел cF` | Показать LSP-клиенты и formatter'ы текущего буфера |
| `[d`, `]d`, `Пробел d` | Предыдущая/следующая ошибка, полный текст ошибки |
| `Пробел cf` | Форматировать через сервер, если он умеет |
| `Пробел rr`, `rc`, `rb`, `rl`, `rt` | Rust: cargo run/check/build/clippy/test |
| `Пробел Gp`, `Gt`, `Gb`, `Gv` | Go: test package, test all, build all, vet all |
| `[h`, `]h` | Предыдущее/следующее git-изменение |
| `Пробел gp`, `Пробел gs`, `Пробел gr`, `Пробел gb` | Git hunk: показать, stage, откатить, blame строки |
| `Пробел tn` | Тест под курсором |
| `[t`, `]t` | Предыдущее/следующее начало теста или Go-бенчмарка |
| `Пробел tf` | Тесты текущего файла |
| `Пробел ts` | Все тесты проекта |
| `Пробел tl` | Повторить последний запуск тестов |
| `F5`, `F9`, `F10`, `F11`, `F12` | Отладка: продолжить, брейкпоинт, шаг поверх, шаг внутрь, шаг наружу |
| `Пробел Dc`, `Пробел Db`, `Пробел Du` | Отладка: продолжить, брейкпоинт, открыть/закрыть UI |
| `Пробел tt` | Открыть терминал снизу |
| `Пробел ?` | Найти сочетание клавиш |

Подсказки появляются при наборе, без иконок: название и текстовый тип варианта
(`Function`, `Variable` и т. п.). Специальный шрифт не нужен.
`Tab` / `Shift-Tab` и `Ctrl-n` / `Ctrl-p`
выбирают вариант, `Enter` принимает выбранный. Без выбора `Enter` вставляет
новую строку. `Ctrl-Space` вызывает подсказки вручную, `Ctrl-e` закрывает их.
Аргументы функции и сниппеты используют встроенные шаблоны Neovim, переход — `Tab`.
При наборе `(`, `[`, `{`, `'`, `"` и `` ` `` закрывающая скобка или кавычка
ставится автоматически; `Backspace` удаляет пустую пару целиком.
Для Go добавлены короткие сниппеты: `err`, `errw`, `test`, `table`, `bench`,
`main`, `ctx`.
Для Rust добавлены короткие сниппеты: `test`, `atest`, `mainr`, `derive`,
`impl`, `match`.
Для Svelte добавлены короткие сниппеты: `comp`, `props`, `state`, `derived`,
`effect`, `if`, `each`, `eacht`, `onclick`, `class`, `bind`, `style`, `btn`,
`form`.
Для JS/TS/JSX/TSX добавлены `desc`, `test`, `testa`, `expect`, `fetchj`, `try`,
`pwt`.

Обычные команды остаются обычными: `/`, `f`, `t`, `%`, `gcc`, `gc`,
`Ctrl-w h/j/k/l`, `:e`, `:w`, `:q`, `:Explore`, `:Lexplore`.
Самодельных команд нет.

Rust/Go команды сохраняют текущий файл и открывают нижний терминал в корне
проекта. `Пробел Gp` запускает `go test` только для пакета текущего файла,
остальные Go-команды работают по `./...`.

`H` слева от строки — рекомендация, `W` — предупреждение, `E` — ошибка.
Для применения исправления поставь курсор на эту строку, нажми `Esc`, затем
`Пробел c a`: откроется окно исправлений. Выбери действие стрелками или набери
часть его названия, затем нажми `Enter`; `Esc` закрывает окно. `u` отменяет изменение,
`:w` сохраняет его. Если сервер не предлагает автоматического исправления,
список действий будет пуст. Полный текст диагностики — `Пробел d`.
`Пробел ci` организует импорты: для Go добавляет и убирает нужные imports,
для TypeScript/JavaScript сначала удаляет unused imports, затем сортирует оставшиеся.

Для рефакторинга куска кода выдели его visual mode и нажми `Пробел Re`, чтобы
вынести функцию, или `Пробел Rv`, чтобы вынести выражение в переменную.
`Пробел RE` выносит функцию в отдельный файл, если язык и контекст это позволяют.
`Пробел Ri` и `Пробел RI` делают inline переменной или функции под курсором.
`Пробел Rs` открывает меню доступных рефакторингов. Для создания отсутствующей
функции, метода или импорта по ошибке по-прежнему используется `Пробел ca`.

## Тесты

Слева от номера строки `T` отмечает начало теста, `B` — Go-бенчмарка.
`]t` прыгает к следующей метке, `[t` — к предыдущей, с переходом через край файла.
`Ctrl-o` возвращает назад. После перехода на тест `Пробел tn` запускает его.
Метки обновляются после редактирования; они показывают расположение, а не результат
теста. Диагностика и метка теста могут отображаться рядом.

Распознаются обычные объявления: Go Test/Example и t.Run в `_test.go`,
Rust `#[test]`, `#[tokio::test]` и `#[async_std::test]`, JS/TS it/test,
Python test-функции, PHP test-методы и Pest it/test, Lua it.
Это лёгкий поиск объявлений, без отдельного парсера или фонового запуска тестов.
Нестандартные обёртки и PHP-тесты только с атрибутом `#[Test]` не отмечаются.
Метка `B` служит для навигации: `tn` не выбирает Go-бенчмарки.
Для бенчмарков пакета есть стандартная команда `:TestFile -run '^$' -bench .`.

Открой тестовый файл и нажми `Пробел tn` или `Пробел tf`. Текущий файл сохраняется,
команда выполняется в обычном терминале снизу. Тесты запускаются только по нажатию.
Корень проекта определяется по go.mod, package.json, composer.json, pyproject.toml
и другим стандартным файлам; для Lua подходит .busted или .luarc.json.

Из терминала `Esc Esc` возвращает обычный режим; `:q` закрывает окно.
Чтобы остановить ещё работающий тест, нажми `i`, затем `Ctrl-c`.
`Ctrl-w p` возвращает в код. Повтор через `Пробел tl` сохраняет текущий файл
и использует корень последнего запуска.

Тестовый инструмент и зависимости должны быть установлены в самом проекте:
например, PHPUnit в vendor, Vitest/Jest в node_modules, pytest в окружении Python.
При использовании обычного .venv активируй его перед запуском Neovim.
Проекты с uv.lock подхватываются автоматически. Для Lua нужен Busted в PATH.
Адаптер node:test запускает весь файл даже через `tn`; у Go, Jest/Vitest,
PHPUnit, Busted и pytest есть выбор отдельного теста.

## Отладка

Отладчик открывается только по нажатию клавиш. Основные клавиши: `F9` ставит
или снимает брейкпоинт, `F5` запускает или продолжает выполнение, `F10` делает
шаг поверх, `F11` шаг внутрь, `F12` шаг наружу. Те же действия есть на
`Пробел Db`, `Пробел Dc`, `Пробел Do`, `Пробел Di`, `Пробел DO`.
`Пробел Du` открывает или закрывает панели отладчика, `Пробел Dr` открывает REPL,
`Пробел Dq` завершает сессию. Условный брейкпоинт — `Пробел DB`.

Go использует Delve (`dlv dap`). Доступны конфигурации: debug package, debug file,
debug test file и attach process.

JavaScript и TypeScript используют `js-debug-adapter`: можно запускать текущий
Node-файл, подключаться к Node-процессу и запускать Chrome для локального URL.
Для браузерной отладки по умолчанию предлагается Vite-адрес
`http://localhost:5173`.

PHP использует `php-debug-adapter` и слушает Xdebug на порту 9003. Для локального
PHP обычно достаточно включить Xdebug в PHP. Для Docker есть отдельная
конфигурация с маппингом `/app` на корень проекта.

## Что оставлено

Всего 17 плагинов с менеджером: lazy.nvim, fzf-lua, flash.nvim, nvim-autopairs,
refactoring.nvim, async.nvim, blink.cmp,
mason.nvim, nvim-lspconfig, conform.nvim, nvim-treesitter,
nvim-treesitter-textobjects, gitsigns.nvim, nvim-dap, nvim-dap-ui, nvim-nio,
vim-test.
При пустом запуске загружаются lazy.nvim и nvim-treesitter.
Поиск и тесты загружаются по нажатию, серверы — по языку файла.
Автодополнение работает на Lua без скачивания или компиляции отдельной библиотеки.
Фронтовые файлы форматируются через Prettier внутри Node-проекта; для `.svelte`
проекту нужен `prettier-plugin-svelte`.

Нет стартового экрана, анимаций, автосессий, отдельного плагина дерева файлов,
постоянного git blame, фоновых тестов, автозапуска отладки и проверки обновлений.
Подсветка синтаксиса, комментарии, строка состояния и терминал — встроенные.
Treesitter уточняет подсветку и даёт переходы по функциям/типам для языков проекта.
Парсеры ставятся в `~/.local/share/nvim/site`, а Gitsigns показывает изменения
только в git-репозиториях.
Ошибки подчёркиваются; всплывающее объяснение появляется по запросу.
Go и Rust форматируются автоматически при сохранении и вручную через `Пробел cf`.
У ty нет форматирования; для Python при необходимости можно запускать
`ruff format` из терминала проекта.

Go проверяет диагностику при сохранении. gopls использует безопасный набор
анализаторов, включая nilness, unused params, unused writes и useany.
Inlay hints для Go и TypeScript/JavaScript настроены, но показываются только
после `Пробел ch`.
Rust использует `rust-analyzer`; `rustfmt` берётся из установленного Rust toolchain.
JS не скачивает пакеты @types автоматически: нужные типы ставятся в проект.
Svelte использует отдельный `svelte-language-server`, а TypeScript-сервер остаётся
для обычных JS/TS/JSX/TSX файлов. ESLint запускается только в проектах, где есть
`eslint.config.*` или `.eslintrc*`. Tailwind-подсказки включаются сервером только
в проектах с Tailwind-конфигурацией.
Lua видит API Neovim только внутри конфига Neovim; обычные Lua-проекты используют
свои настройки. Psalm запускается только в PHP-проектах с `psalm.xml`
или `psalm.xml.dist`; Intelephense остаётся основным PHP-сервером для навигации
и подсказок.

## Установка на другую машину

Нужны Neovim 0.12.5+, Git, fzf > 0.36, ripgrep (`rg`), tar, curl,
tree-sitter-cli 0.26.1+ и C compiler, а также инструменты нужных языков:
Go, Rust/rustup с rustfmt, Node/npm, PHP/Composer, Lua/Busted, Python/uv
или venv.
Положи эту папку в `~/.config/nvim` либо сделай ссылку. При первом запуске lazy.nvim
скачает плагины; версии зафиксированы в lazy-lock.json.

Один раз установи серверы стандартной командой Mason:

```vim
:MasonInstall gopls rust-analyzer typescript-language-server svelte-language-server eslint-lsp html-lsp css-lsp json-lsp tailwindcss-language-server emmet-language-server prettier intelephense psalm lua-language-server ty
```

Для отладки установи адаптеры:

```vim
:MasonInstall delve js-debug-adapter php-debug-adapter
```

Для Treesitter один раз установи настроенные парсеры:

```vim
:TSInstallConfigured
```

На текущей машине Psalm пока не установлен, остальные серверы уже установлены.
На текущей машине tree-sitter-cli 0.27.0 установлен в `~/.local/bin`.
Обновления запускаются вручную: `:Lazy` для плагинов, `:TSUpdate` для парсеров
и `:Mason` для серверов. Для проверки — `:checkhealth vim.lsp`
и `:checkhealth nvim-treesitter`.
Подсказка по новым клавишам лежит в `nvim/ADDED_COMMANDS.md`.

Документация: [Neovim LSP](https://neovim.io/doc/user/lsp/),
[ty](https://docs.astral.sh/ty/editors/),
[vim-test](https://github.com/vim-test/vim-test),
[fzf-lua](https://github.com/ibhagwan/fzf-lua),
[blink.cmp](https://cmp.saghen.dev/configuration/completion),
[nvim-autopairs](https://github.com/windwp/nvim-autopairs),
[nvim-dap](https://github.com/mfussenegger/nvim-dap),
[nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter),
[refactoring.nvim](https://github.com/ThePrimeagen/refactoring.nvim),
[gitsigns.nvim](https://github.com/lewis6991/gitsigns.nvim).

## Проверка на текущей машине

Neovim 0.12.5, 6 октября 2026: конфиг загружается в headless-режиме.
Проверена миграция `nvim-treesitter` на новый `main` API, `:checkhealth
nvim-treesitter`, загрузка `refactoring.nvim`, `Пробел Re` для Go extract
function на официальном fixture плагина после `gofmt`, `Пробел Rv` для
TypeScript extract variable и подключение `rust_analyzer` к маленькому
Cargo-проекту.
Проверены настройки gopls и typescript-language-server 6.0.0, `Пробел ci`
для Go и TypeScript, а также root guard для несуществующего JS/TS пути.
Для Go refactoring.nvim используется локальный запрос
`queries/go/refactor_scope.scm`: текущий Go-парсер Treesitter хранит выражения
прямо внутри `block`, а не в узле `statement_list`, который ожидает плагин.
Также проверено, что gopls не пытается загрузить несуществующий `/home/darklord/syn`
как workspace folder.
Neovim 0.11.6, 21 сентября 2026: подсказки и переход к определению проверены
на небольших проектах всех пяти языков. Проверены окно автодополнения с принятием
варианта, поиск файлов и текста, запуск тестов и повтор после изменения кода.
Падающий тест сохраняет ненулевой код выхода; повтор работает и после смены каталога.

Пустой запуск без интерфейса: медиана трёх последовательных запусков 21 сентября
2026 уменьшилась с **48,23 до 9,86 мс**. Это время запуска редактора, без ожидания
языкового сервера и индексации проекта. После добавления фронтовых плагинов
пустой старт по-прежнему не должен поднимать LSP и проектные инструменты.

## Резервная копия

Исходный конфиг и результаты проверки лежат в
`~/.local/state/nvim-backups/20260921-150235/`.
Папка `original-config` — конфиг до переделки, `plugins` — убранные плагины.
Чтобы откатиться, закрой Neovim, перенеси ссылку `~/.config/nvim` в другое место,
скопируй `original-config` обратно в `~/.config/nvim` и верни содержимое `plugins`
в `~/.local/share/nvim/lazy/`.
